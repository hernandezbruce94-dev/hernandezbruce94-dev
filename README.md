# Bruce L. Hernandez

I write about turning security requirements into working controls—and keeping evidence of the result.

**Configured? Prove It.** is the question behind the work here: what should a control allow, what should it deny, and what evidence shows the decision?

## Security engineering & architecture portfolio

[Explore the portfolio](portfolio/README.md): a complete architecture study, eight practical guides, four proposed project concepts, reusable templates, and a locally tested offline evidence-index checker. Includes an interview walkthrough and explicit evidence labels.

These are collaboratively drafted educational designs and synthetic demonstrations; implementation status and authorship context are documented in the portfolio.

**New: [Access Boundary Lab](portfolio/labs/access-boundary/README.md).** A free offline browser lab: change a request, inspect tenant/action/expiry boundaries, and distinguish modeled decisions from evidence. Includes regression tests, a threat model, and interview challenge cards.

## What you'll find here

- **Identity and least privilege:** access decisions, scope, and verification.
- **Network and cloud controls:** policy examples, queries, and test cases.
- **Operational evidence:** verification records, change checklists, and control registers.

The companion examples use fictional values and placeholders. **Documented** behavior and **Lab-tested** results are different evidence levels; review the repository's scope and test in an authorized non-production environment before adapting examples.
